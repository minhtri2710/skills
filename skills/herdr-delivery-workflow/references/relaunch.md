# Relaunch recovery

A Lead or Supervisor seat recovering from compaction or relaunch reads this before acting.

For a relaunch that retires a predecessor, follow `supervisor.md ## Handoff`: read the exit/handoff outcome from `herdr pane read`, not `herdr agent list`; `agent_prompt_stalled` or a non-zero prompt return is not itself failure; never PID-kill.
On `/exit`, expect the Claude Code prompt `You have N unsent feedback drafts`. Whether to send or discard those drafts is a Human decision. After the Human answers, the Human or the Supervisor as the Human's hands sends `herdr agent send-keys <seat> esc` to discard or the send key (Enter) to send; the outgoing seat never chooses or performs this feedback action on its own initiative.

After compaction or relaunch, before acting, run this checklist in order:

1. Confirm the doctrine by comparing every installed file with its deployed head: enumerate with `git ls-tree`, hash each installed file with `git hash-object`, and compare with `git rev-parse "${deployed_head}:<path>"` (braced so zsh cannot treat `:` as a history modifier). All later steps use that text; skipping it means running the old checklist while reporting the new version.
2. If a relaunch/attention entry names a NEXT item or next scope, quote that line verbatim from a named staffing/backlog NEXT section or `scripts/slices_ready.py` output, include that source file path in the entry, and confirm it with `scripts/relaunch_entry_check.py --verify --block-file <next-item-block> --source-file <named-source>`; the quote must carry its gate ids and must never be reconstructed from memory.
3. Report the doctrine file count only as the computed tracked/installed/drifted triple printed by `scripts/relaunch_entry_check.py --count --repo <repo> --head <deployed-head> --skill-path <skill-path> --installed-path <installed-skill-path>`, never as a recalled number.
4. If an installed skill lacks tracked source at a known head, re-read installed files and check by content that every site changed by the last redeploy is new, recording the confirmation as sampled rather than exhaustive.
5. Reconcile past pushes, merges, and PR mutations since the ledger's last line through `scripts/gate_row.py`; record past events as `--record reconstruction --head <branch>@<exact full 40-hex SHA>` with their source, and use base `0000000000000000000000000000000000000000` for a first publication to an empty remote. Run `scripts/gate_row.py --check --ledger <path>` after each row.
6. Unconditionally, in the relaunch/attention entry, record both the resolved path of `scripts/gate_row.py` and a real `gate_row.py --check` result naming the row it checked, even when zero ledger rows were reconstructed. A failed check means the row is absent or invalid and must be redone through `scripts/gate_row.py`, not hand-written.
7. Re-establish current branch, full `HEAD`, porcelain, and stash list.
8. For a Supervisor seat, first read the newly appended mailbox header index with `scripts/mailbox.py --file <path> --headers --since <last-read ISO>`, then pull full bodies only for `ATTENTION` or open-question answer headers with `--since` without `--headers`, or a bounded `--last`/targeted read, rather than rereading the whole file.
9. Reconcile live Peers and owed reports with `scripts/roster.py`, then run its `--drift` check against the project config for every staffed Peer (`herdr-cli.md`, "Start and drive an agent"); carry each `DRIFT` line or refusal into the step-10 entry.
10. Last, when a Supervisor is recorded, append one compaction/relaunch attention entry carrying reconciled `HEAD`, branch, open gates, and owed reports to `~/.herdr/projects/<project-slug>/supervisor-mailbox.md` as the delivery with `scripts/mailbox.py --file <path> --append --from <lead> --to supervisor --repo <checkout> --event "<one line>" --attention <event> --stdin` (`templates/mailbox-entry.txt`); it writes the header, then reads back the last header and wakes the Supervisor mechanically, without `--wait` and with no retry by the Lead; the prompt is not the payload. When `Supervisor: none` was recorded, use the Lead-owned no-Supervisor path in `lead.md`, "Supervisor and attention events". An UNSENT entry follows `lead.md`, "Supervisor and attention events". If the seat needs the cause or content of an older decision, rather than exact git, ledger, or mailbox state covered by the reconciliation above, follow `herdr-cli.md`, “Recall past records”, instead of rereading run directories. If the seat cannot continue safely, report `BLOCKED` to the Human with preserved custody evidence, not a fresh delivery.
