# Relaunch recovery

A Lead or Supervisor seat recovering from compaction or relaunch reads this before acting.

After compaction or relaunch, before acting, run this checklist in order. First confirm the doctrine by comparing every installed file with its deployed head: enumerate with `git ls-tree`, hash each installed file with `git hash-object`, and compare with `git rev-parse "${deployed_head}:<path>"` (braced so zsh cannot treat `:` as a history modifier). All later steps use that text; skipping it means running the old checklist while reporting the new version. If a relaunch/attention entry names a NEXT item or next scope, quote that line verbatim from a named staffing/backlog NEXT section or `scripts/slices_ready.py` output, include that source file path in the entry, and confirm it with `scripts/relaunch_entry_check.py --verify --block-file <next-item-block> --source-file <named-source>`; the quote must carry its gate ids and must never be reconstructed from memory. Report the doctrine file count only as the computed tracked/installed/hash-mismatch triple printed by `scripts/relaunch_entry_check.py --count --repo <repo> --head <deployed-head> --skill-path <skill-path> --installed-path <installed-skill-path>`, never as a recalled number. If an installed skill lacks tracked source at a known head, re-read installed files and check by content that every site changed by the last redeploy is new, recording the confirmation as sampled rather than exhaustive. Then reconcile the gate ledger against every merge, push, and PR mutation since its last line through `scripts/gate_row.py`; record reconstructed ledger lines as `reconstruction` with their source and run `scripts/gate_row.py --check --ledger <path>` after each row. A failed check means the row is absent or invalid and must be redone through `scripts/gate_row.py`, not hand-written. Re-establish current branch, full `HEAD`, porcelain, and stash list; for a Supervisor seat, first read the newly appended mailbox header index with `scripts/mailbox.py --file <path> --headers --since <last-read ISO>`, then pull full bodies only for `ATTENTION` or open-question answer headers with `--since` without `--headers`, or a bounded `--last`/targeted read, rather than rereading the whole file; reconcile live Peers and owed reports with `scripts/roster.py`; last, append one `templates/mailbox-entry.txt`-shaped compaction/relaunch attention entry carrying reconciled `HEAD`, branch, open gates, and owed reports to `~/.herdr/projects/<project-slug>/supervisor-mailbox.md` as the delivery, then run `scripts/mailbox.py --file <path> --wake supervisor`; it reads back the last header and performs the best-effort wake mechanically, without `--wait` or retry; the prompt is not the payload. If no header is returned, the entry is UNSENT and no wake runs: correct it to the template and re-append it. If the seat needs the cause or content of an older decision, rather than exact git, ledger, or mailbox state covered by the reconciliation above, follow `herdr-cli.md`, “Recall past records”, instead of rereading run directories. If the seat cannot continue safely, report `BLOCKED` to the Human with preserved custody evidence, not a fresh delivery.
