# Relaunch recovery

A Lead or Supervisor seat recovering from compaction or relaunch reads this before acting.

After compaction or relaunch, before acting, run this checklist in order. First confirm the doctrine by comparing every installed file with its deployed head: enumerate with `git ls-tree`, hash each installed file with `git hash-object`, and compare with `git rev-parse "${deployed_head}:<path>"` (braced so zsh cannot treat `:` as a history modifier). All later steps use that text; skipping it means running the old checklist while reporting the new version. If an installed skill lacks tracked source at a known head, re-read installed files and check by content that every site changed by the last redeploy is new, recording the confirmation as sampled rather than exhaustive. Then reconcile the gate ledger against every merge, push, and PR mutation since its last line (the append may have been dropped while the write happened); re-establish current branch, full `HEAD`, porcelain, and stash list; for a Supervisor seat, first read the newly appended mailbox header index with `scripts/mailbox.py --file <path> --headers --since <last-read ISO>`, then pull full bodies only for `ATTENTION` or open-question answer headers with `--since` without `--headers`, or a bounded `--last`/targeted read, rather than rereading the whole file; reconcile live Peers and owed reports with `scripts/roster.py`; last, send the compaction/relaunch attention event with `herdr agent prompt supervisor` without `--wait`, carrying reconciled `HEAD`, branch, open gates, and owed reports so it carries the reconciliation. Record reconstructed ledger lines as `reconstruction` with their source. If the seat needs the cause or content of an older decision, rather than exact git, ledger, or mailbox state covered by the reconciliation above, follow `herdr-cli.md`, “Recall past records”, instead of rereading run directories. If the seat cannot continue safely, report `BLOCKED` to the Human with preserved custody evidence, not a fresh delivery.
