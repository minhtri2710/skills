### Validation-run custody

**Validation-run custody.** An external validation pipeline (such as a `no-mistakes` run) is one Lead-owned singleton. Never start another run for the same head, interrupt its validation agent, apply its finding outside the run, or drive it from an Engineer's seat. At intake, read and record which pipeline steps auto-run external writes and which pause for a decision; do not assume a named Human-gated step will pause if the pipeline can auto-approve it. Preserve run ID, exact head, branch, findings, every response, and terminal outcome beside the verification ledger, kept across correction rounds; a timed-out or inconclusive step is a Human gate, never `PASS`. Classify findings: mechanical, low-risk findings the pipeline owns are handled inside it; the Lead's accept/fix/dismiss command through the pipeline's interface is not a Human gate unless the Human reserves it in their own words. A finding challenging Human intent or touching destructive scope, security, credentials, external effects, or material scope is a Human gate: route it, pause the same run, and resume through its own command. A quiet monitor signals liveness, not terminal evidence; when a wake reveals that the pipeline made an external write, append its gate-ledger row through the `scripts/gate_row.py` rule in "Gates and ledger" and run its required `--check` before reporting it; an auto-cleared gate is not evidence that the step paused. When the forge reports the PR merged or closed after checks passed, reconcile this run's lifecycle, not a new delivery. On observed terminal state, write `templates/validation-run-custody.txt`; copy its fixed CUSTODY and ESCALATION lines verbatim. Do not abort, rebase, delete the branch, or rewrite the head to fix a stuck lifecycle; report the evidence gap.
